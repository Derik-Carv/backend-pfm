Objetivo

API do sistema PFM. O Swagger em /docs é a referência dos schemas executáveis; esta página explica arquitetura, operação, integração e regras do sistema.

Configuração rápida

cp .env.example .env
bun install
bun run dc

A API local usa a porta configurada em PORT, normalmente 3336. Health check: GET /public/health.

Seed essencial

O startup cria roles, o administrador, status de serviço e tipos de NF. Clientes, serviços, movimentações e NFs são criados pelas APIs. Não há dados demonstrativos automáticos.

Autenticação e API

Faça POST /public/login. A resposta inclui o token e passwordChangeRequired. Envie o token como Authorization: Bearer TOKEN. Rotas públicas: login, register e health. Se passwordChangeRequired for true, use PATCH /account/password com a senha temporária e a nova senha antes de liberar a aplicação.

Fluxo de NF

  1. Busque GET /types.
  2. Busque clientes em GET /clients?page=1&limit=10.
  3. Busque serviços em GET /services/list?clientId=UUID.
  4. Envie POST /nf/ como multipart com file PDF e nf JSON.

movimentationId é opcional. NFs podem ser listadas e desativadas em /notes.

Administração

A API administrativa é exclusiva para o papel administrator e usa uma superfície única:

GET   /admin/data/:table?page=1&limit=20&status=all
GET   /admin/data/:table/:id
POST  /admin/data/:table
PATCH /admin/data/:table/:id

Tabelas: roles, users, clients, movimentations, types, status-services, services, notes e bundled. GET usa paginação; status pode ser all, active ou inactive. Senhas nunca são retornadas.

Logs e auditoria

Defina AUDIT_LOG_ENABLED=true. POST, PUT, PATCH e DELETE geram eventos estruturados no logger e, em produção, no Axiom. O evento contém ator, papel, rota, método, status, sucesso e request ID.

AXIOM_TOKEN=...
AXIOM_DATASET=backend-pfm
AUDIT_LOG_ENABLED=true
LOG_LEVEL=info

No Axiom, pesquise audit:true. Authorization, tokens, senhas e CPF são redigidos.

Produção

bun run dc:prod
docker compose -f compose.yaml -f compose.production.yaml logs -f backend

O compose de produção usa a imagem compilada, reinicia serviços, executa o schema e verifica o health check. Use segredos reais somente por variáveis de ambiente ou secret manager.

Política de mudanças

Nova rota, alteração de schema, permissão, migration, configuração ou evento de auditoria deve atualizar o Swagger, esta página, o README quando afetar integração e CHANGELOG.md com data e impacto.

Valide antes de publicar: bun run typecheck, bun run build e git diff --check.
